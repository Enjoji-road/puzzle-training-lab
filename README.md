# Puzzle Training Lab

白黒ルート、配置推理、覆面算を、自分の推理を記録しながら解く日本語のWebアプリです。全47問を収録しています。スマートフォンでは画面下部から問題一覧・重点復習・学習記録に移動できます。

## 遊び方

1. ホームのおすすめ、または問題一覧から一問を選びます。4×4の基本から復習するなら「小径の分かれ道」、二つの条件をつなぐ練習なら「折れない渡り廊下」が入口です。
2. ルート問題では白か黒を選び、空きマスに置きます。接した白は自動でつながります。対応表では、行と列の交点に○か×を置きます。覆面算の先頭の0や数字の範囲は「遊び方・ルール」と「手がかり」で確認できます。
3. 手がかりは最初から表示されます。手がかりを選ぶと、盤面の上にその条件が残ります。ルート盤面の「全体表示」では離れたマスの位置を一度に見渡せます。「調べる」でマスを選び、メモや根拠を保存できます。置いた値や除外した候補を、別の値や候補の根拠につなげられます。
4. 場合分けするなら「仮定・チェックポイント」から仮定に名前を付けます。それ以降の入力には「?」と破線が付きます。「仮定前に戻す」で、そこから導いた値・候補・メモ・根拠を一緒に取り消せます。前からあった値はそのまま残ります。
5. 複数の案を残すには、仮定の途中で「ここを保存」します。別の案を試した後も、チェックポイントから当時の仮定とその出発点を復元できます。一手単位のUndo・Redoにも対応します。全入力が正解と照合できた段階で、その仮定を解決済みにします。
6. 「矛盾を点検」は見えている印から、数字超過、行き止まり、輪、孤立、候補不足、条件違反などを探します。点検を通過した途中盤面には、まだ確かめるべき条件が残り得ます。「解答を判定」は全部の入力がそろってから行います。
7. ヒントは着眼点・推理の接続・具体的な一手の順です。段階解説は別の操作で開き、手順ごとに進めます。最後の手順の後に、間違えやすい点と応用のコツが表示されます。

## 学習記録と重点復習

問題、通常・復習の区別、正誤、段階別のヒント利用、解説の閲覧、巻き戻し・Undo・Redo・再挑戦、仮定、検出した矛盾と復帰を挑戦ごとに記録します。復習では、選んだスキルを使う問題の中から、困ったと記録した問題やヒントを使った問題などを優先し、未挑戦の別問題も表示します。「振り返り」で困ったスキルを自分で指定できます。苦手分析には対象問題数と挑戦回数を併記します。

重点復習ではジャンルとレベルを組み合わせて絞れます。たとえば「候補管理」「覆面算」「Lv.5」を選ぶと、その条件に合う問題を練習できます。

途中再開と学習記録にはブラウザのlocalStorageを使います。同じURLを同じブラウザで開いてください。端末変更、別URLへの移行、ブラウザデータの削除で記録を引き継ぐ場合は「学習記録 → 記録のバックアップ」でJSONを書き出し、移行先で読み込みます。読み込み前にファイルの内容を検証し、既存記録を置き換える前に件数を表示します。保存容量を超えた場合は画面に知らせ、現在のタブから書き出せます。

## ローカルで起動する

Python 3.10以上とNode.js 20以上を使います。依存パッケージのインストールやビルドは不要です。

```sh
python -m http.server 8080 --directory dist
```

ブラウザで `http://localhost:8080/` を開きます。ブラウザはHTTP経由で問題データを読み込みます。

## 問題を追加する

1. 近い形式の問題を複製するか、下記の候補生成を使います。永続的に一意な `id`、`genre`、`level`（1〜5）、`title`、`goal`、`intro`、`skills` を設定します。既存IDや選択肢の文字列は学習記録から参照されるため、別問題として作り直すときは新しいIDを付けます。復習専用には `"pool": "review"` を付けます。
2. `rules` に共通ルール、`clues` にID付きの条件を記述します。答えの保存形式は `solution` の「編集欄のキー → 文字列」です。
   - ルートは `board.cells` を行優先で並べます。固定色は `given: "W" / "B"`、両端は `S` と `G` です。数字・曲折・白数・同異色・一方向の条件は `board.constraints` に記述します。固定マスは解答入力から除きます。
   - 配置推理は `board.tables` に行・選択肢を置き、`clues[].test` に式の木を書きます。`at` は指定行の選択肢番号（1始まり）、`inv` は指定番号を使う行、`row` は行番号から値を参照します。`eq`、`lt`、`distance`、`and` などで関係を表せます。複数表の結合例は `logic-3` です。
   - 覆面算は `board.symbols` に内部キーと表示記号、`board.tables` に数字の候補を記述します。条件は `domain`、`equation`（加減算）、`less` です。式の語にある小文字は記号、算用数字は定数です。先頭の0を含むルールは本文にも明記してください。
3. `hints` に3段階、`steps` に手順を置きます。各項目に `text` と参照した `clues` を付け、具体的に確定する値を `facts` に記述します。数値関係や反証にはジャンル別の `checks`、`cases`、`claims` も使えます。手順全体で全入力欄の値を導き、最後に `pitfall` と `transfer` を書きます。
4. 手がかりと解法の自然さ、ヒント3で続きを考える余地、指定レベルとの整合を作問レビューします。済んだ項目を `review.levelReviewed` と `review.explanationReviewed` に記録し、`techniques` に推理技法、`notes` に判断理由を書きます。初見プレイヤーの体感は試遊で確かめます。
5. `puzzles.py check` で一意性・説明の確定事項・仮定の棄却・重複を検査し、通った候補を `puzzles.py register` で登録します。新しい制約を使う場合は、探索器と画面上の点検も更新してください。

### Lv.4・5の候補を生成する

```sh
python scripts/puzzles.py generate --genre route --level 5 --seed 34 --count 2 --output ./route-drafts.json
```

`--genre` は `route`、`logic`、`symbol` から選べます。`--count` を省略すると1問です。同じカタログとシードで再現でき、候補が見つからなければ別のシードで試せます。

- 白黒ルートは登録済みの区画構造を土台に、数字・同色や異色・条件文などの候補を組み替えます。新しい地形を作る場合は白黒盤面を作問してから登録できます。
- 配置推理は三つの表を便番号で結び、同じ便・順番・間隔・発言の真偽を組み合わせます。
- 覆面算は繰り上がりや借りを含む加減算を組み合わせ、複数式を同時に成立させる割り当てを求めます。

出力は `dist/` の外にある候補です。候補の解と条件を適用するごとの絞り込み数が得られます。解説・ヒントと作問レビューは、第4手順までに入力します。自動生成された候補の一意性と、文章で自然に推理できることは、それぞれ検査します。

```sh
python scripts/puzzles.py check ./route-drafts.json
python scripts/puzzles.py register ./route-drafts.json --file advanced-routes-next.json
python scripts/verify.py
python -m unittest discover -s tests -p 'test_*.py'
node --test tests/*.test.mjs
```

登録は新しいデータファイルとカタログだけを書き換えます。検査で落ちた候補や作問レビュー前の候補は読み込み対象に入りません。`python scripts/verify.py --json` は、問題別の解数・条件を単独で外したときの候補数・機械推定を出力します。機械推定は解説が使う条件数、条件を組み合わせた段階、反証、途中の関係を使う目安です。

重複検査は題名とIDに加え、ルートの回転・反転や余白、配置推理の表示名、覆面算の記号名や足す順序などを除いた盤面・制約を比較します。解き筋が似た別問題や任意の論理等価は、一覧での作問レビューで確認します。

## GitHub Pagesへ公開する

本番前の試遊リンクはこの変更のPull Requestに掲載しています。試遊版とPagesでは学習記録の保存先が分かれるため、移行時にはJSONを使ってください。

1. 試遊後にこのプロジェクトのPRを `main` にマージします。
2. リポジトリの **Settings → Pages → Build and deployment → Source** で **GitHub Actions** を選びます。
3. **Actions → Publish verified Pages → Run workflow** から `main` を指定します。検証とテストに成功すると `dist/` を公開します。以降の再公開も同じ操作です。
4. 想定の本番URLは [Puzzle Training Lab on GitHub Pages](https://enjoji-road.github.io/puzzle-training-lab/) です。

[GitHub Pagesの公開元設定](https://docs.github.com/en/pages/getting-started-with-github-pages/configuring-a-publishing-source-for-your-github-pages-site)
